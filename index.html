1) Overview: what is LoRaFBSNet?
This is a Spiking Neural Network (SNN) in the ResNet family (similar to SEW-ResNet from SpikingJelly) with two extra mechanisms:
1. Local recurrence: each stage's own output from the previous time step (y) is re-injected into the same stage (short-term memory).
2. Top-down feedback: outputs of deeper stages are routed back to shallower stages (like top-down pathways in recurrent vision models).

Overall flow: Input [T,B,3,H,W] → Stem → 4 recurrent stages → AvgPool → Linear → [T,B,num_classes]
Key point: the input is a time sequence. The Stem runs on all T frames first, then the for t in range(T) loop runs all 4 stages once per time step.
2) sew_function — merging the main path and the shortcut
At the end of every residual block, the conv output is merged with the identity: 
ADD → x + y            (plain sum, like ResNet)
AND → x * y            (multiplicative / AND)
OR  → x + y - x * y    (fuzzy / probabilistic OR)
Any other cnf string raises NotImplementedError.
3) BasicBlock & Bottleneck — spiking residual blocks
Exactly like classic ResNet, but every BatchNorm is followed by a LIF neuron (Leaky Integrate & Fire) with ATan surrogate gradient and detach_reset=True:
• BasicBlock: two 3×3 convolutions. Output channels = planes (expansion=1).
• Bottleneck: three convolutions (1×1 reduce → 3×3 → 1×1 expand). Output channels = planes × 4 (expansion=4).
• If stride changes or channel counts differ, a downsample branch (Conv 1×1 + BN) followed by downsample_sn (a LIF) aligns the identity path.
• Convolutions come from spikingjelly.clock_driven.layer (SNN-compatible versions).
Subtle point: in _make_layer, the downsample Sequential only contains Conv+BN — the LIF (downsample_sn) is applied manually in the block's forward. The blocks after the first one are created without a downsample argument (stride=1 assumed), matching standard ResNet construction.
4) FeedbackConnection — the feedback path (deep → shallow)
Job: take a deep stage's output (small spatial size) and transform it into the shallow stage's size and channel count:
1. Checks source_stride % target_stride == 0.
2. scale_factor = source_stride // target_stride must be a power of 2.
3. Repeats this chain log2(scale_factor) times: 
ConvTranspose2d(3×3, stride=2, groups=C) → BatchNorm → LIF
(Depthwise upsample — channel count stays constant during upsampling.)
4. If source channels ≠ target channels, adds Conv2d(1×1) + LIF to match.
Hidden bug: if scale_factor == 1 (equal strides), no module is built at all, but forward still uses self.feedback → AttributeError! In this architecture it never happens (target stride is always smaller), but it would break if you added a same-resolution feedback edge.
5) ConvRecurrentContainer — the heart of the model
Each stage is a recurrent container wrapping the ResNet blocks (sub_module). Inputs are concatenated: 
C_total = in_channels + out_channels + total_external_feedback_channels
Internal flow at each time step t: 
x(t) ──────┐
y(t−1)─────┤→ [×recurrent_scale] → Concat → PWConv 1×1 (C_total→C_in) → BN → LIF → sub_module → y(t)
FB(t−1)────┘
• Recurrent state prep (_prepare_recurrent_state): if y is None (first step) → zero tensor. Otherwise: ConvTranspose2d(depthwise, stride=stride) → BN → LIF → (if needed) interpolate nearest to match current H×W.
• External feedback: spatial mismatch → interpolate nearest; channel mismatch → RuntimeError; no feedback → zeros.
• self.y is registered via register_memory so functional.reset_net can clear it.
Why does the PWConv map back to C_in? Because the sub_module (the ResNet stage) expects exactly in_channels input channels. Recurrent + feedback information is "compressed" before entering the residual blocks.
6) Feedback graph (_build_feedback_graph)
For every source stage and every distance d = 1..feedback_range: edge (source, source−d) is created (if target ≥ 0).
E.g. feedback_range=2: edges (2→1),(3→2),(3→1),(2→0),(3→0)… i.e. deep information flows back to shallow stages.
Subtle point: when building incoming_feedback_channels, the code appends stage_channels[target] (not source). Since the FeedbackConnection ends with a 1×1 conv mapping to the target's channels, each incoming feedback edge contributes exactly stage_channels[target] channels — so a stage's external feedback width = number of incoming edges × its own channel count.
7) Time loop in forward — feedback is delayed by one step
for t in range(T):
    previous_outputs = [y1, y2, y3, y4]   # the y's from step t−1 !
    feedback_l1 = _compute_feedback(target=0, previous_outputs)
    x1 = recurrent_layer1.single_step_forward(xt, feedback_l1)
    ... (same for layers 2..4)
    logits = fc(flatten(avgpool(x4)))
Feedback has a one-step delay: because previous_outputs is read before running the stages, the feedback layer 1 receives at step t is based on other stages' outputs from step t−1. At t=0 all feedbacks are None (since reset_state is called at the start of forward).
Note: because reset_state runs at the start of every forward, neuron states persist across time steps within one call but are cleared between calls.
The print statements (fusion_inputs and feedbacks) are debug-only and should be removed for real training — they severely slow things down.
